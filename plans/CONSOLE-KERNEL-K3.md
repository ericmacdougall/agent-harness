# K3: legacy import, not wired

Status: draft for plan review. This slice implements "Old sessions: one-way import" in [the kernel plan](CONSOLE-KERNEL.md) as a library with tests. Nothing calls it until K10. No real data directory is read or written; tests use temp directories and fixtures generated by `6172744` code.

## What 0.1.0 actually does (read from `6172744`)

- **Journal.** `sessions.jsonl`, one JSON record per line, `Sync` after each record. Records over 60,000 bytes are refused, and the file is capped at 8 MiB. Each record is a full snapshot, and its kind is told only by `state`. `restore()` (journal.go:11-106) decides the restored state:
  - Last record per session wins.
  - A `closed` session is dropped.
  - Only the last 24 sessions are kept.
  - Records with `reviewParent` are routed to reviews.
  - Records with `taskId` or `checkpoint` are routed to checkpoints.
  - `checkpoint:*` states are skipped, as are records with an empty `sessionId` or `providerId`.
- **Bad lines.** Any line that does not parse as JSON (torn tail, corrupt line, empty line, non-JSON) and any line over 64 KiB makes 0.1.0 exit without starting. So the sentinel approach holds: a non-JSON `sessions.jsonl` keeps 0.1.0 from starting, and it can never recreate an empty journal.
- **Lock.** `console.lock` in the data directory, taken before the journal is read and held for the whole process life:
  - Unix: `flock(LOCK_EX|LOCK_NB)`.
  - Windows: `LockFileEx` exclusive, byte 0, length 1.
  The event log takes the same lock in the same way, so a running 0.1.0 and the importer exclude each other.
- **Queue files.** `queued-inputs/<sha256(sessionId)>.json` plus an optional `.previous`. They are decoded strictly: unknown fields, duplicate keys and trailing data are all refused. Their fields are checked against the journal's checkpoint, and `.previous` is merged by `mergeQueueCandidates`. Only restored sessions' files are ever read, so orphan files stay on disk untouched.

## Scope

1. **`internal/legacyimport` decoder.**
   - A pure function from journal bytes to a typed `Legacy` value: sessions, reviews, checkpoints, and a `torn` flag.
   - It follows `restore()` rule for rule, including the 24-session window.
   - It enforces the same limits: 8 MiB, 64 KiB per line, 60,000-byte records.
   - A torn final line (no trailing newline, does not parse) is reported, so the importer can set it aside.
   - Any other unparseable line, or a `state` outside the closed set seen in `6172744`, refuses the import and changes nothing.
2. **Queue decoder.**
   - A pure, bounded, read-only port of `restoreInputs` and `mergeQueueCandidates`, with the same limits and the same strict decoding. Its output is typed held inputs per session. Payloads stay in place, and only references and hashes are carried.
   - A corrupt queue file gives a per-session `unknown` marker and does not refuse the import.
   - Orphan files are listed, not read into sessions.
   - An entry with no `DirectoryIdentity` is marked so a later release skips the identity-guarded cleanup.
3. **Mapping to facts.**
   - One `LegacyImported` per restored session, following the receipt table in the kernel plan:
     - `final` maps to `final`.
     - `rejected` and `paused` map to `rejected`.
     - `intent`, `accepted` and `unknown` map to `unknown`.
     - `abandoned` maps to `abandoned`.
     - Sessions whose last records carry no request id (`created`, `cwd`, `admission_failed`) import with no receipt.
   - Task identity rides on the existing `LegacyImported` fields.
   - Then one `LegacyImportCompleted` whose digest is SHA-256 of the journal bytes it read.
   - All facts go in one `Append`, so the import commits as one transaction or not at all.
4. **Import driver.** The order of operations:
   1. Take `console.lock` by opening the event log, which takes it.
   2. Read and decode.
   3. Append.
   4. Set aside a torn tail into `sessions.jsonl.torn-<ts>`.
   5. Swap: write a temp sentinel, hard-link `sessions.jsonl` to `sessions.jsonl.imported-<ts>`, rename the sentinel over `sessions.jsonl`, then fsync the directory.

   Crash barriers sit between the steps, as in the event log. Recovery on the next open:
   - A real `sessions.jsonl` whose digest matches the projection's `LegacyImported` means the swap is unfinished: finish it.
   - A sentinel means the import is done.
   - A real `sessions.jsonl` with a different digest after a completed import refuses and names `--reimport`.
   - A missing `sessions.jsonl` with no import imports nothing and completes with the digest of empty input.
5. **Rollback and `--reimport`, both directions, as library functions.**
   - Rollback takes the lock and replaces the sentinel with the newest `.imported-*` file.
   - `--reimport` imports that journal under new session identities `<old>:g<N>`, where N is the import generation.
   - Earlier sessions stay as they are, read-only.
6. **Kernel change, one row.** Table 2 `LegacyImportCompleted` today requires "not already completed", so a reimport cannot record. New rule:
   - The digest must be nonempty and differ from the current one.
   - The fact sets `LegacyImported` to the new digest and increments a new projection field, `LegacyGeneration`.
   - `LegacyImported` session facts are legal only while `LegacyGeneration` matches the generation encoded in their ID suffix (none for generation 1).

   The separate model agent updates its model from the table first, as before.
7. **Event log holds its own projection (the N1 TODO).**
   - `Log` keeps the projection it last published.
   - `Append` checks the caller's `LastSeq`, as now, and judges `MustAppend` and `Reduce` against its own copy instead of the caller's, then advances that copy.
   - The importer is a second `Append` caller, which is why this lands here.
   - The signature stays the same, and the caller's projection becomes a sequence check only.

## Deferred, with reasons

- `LegacyInputHeld`, synthetic sessions for orphan queue files, and `ReviewOutcome{unknown}` for review records are reserved kinds with no K1a table. K3 decodes their inputs and tests the decoders. Their facts arrive with K1c (inputs) and K1d (reviews and checkpoints). K10 wires import only after those slices, so no import runs before its facts exist.
- No CLI flag. `--reimport` and rollback are library functions here; K10 exposes them.

## Risks and negative cases

- **Malformed, old or future data:** torn tail, corrupt complete line, empty line, line over 64 KiB, file over 8 MiB, unknown `state`, unknown queue field, duplicate JSON key, `.previous` only, `.previous` that disagrees, objective hash mismatch, `null` line. Each has an expected outcome, and each refusal changes nothing on disk.
- **Concurrency:** a held `console.lock` (a running 0.1.0, or a second importer) refuses with nothing changed. This is tested with a real second process holding the lock on Linux, Mac and Windows.
- **Crash at each step:** child process killed at each barrier, then reopen. The end state is always one of three: not imported and untouched, imported with the swap finished by recovery, or imported and swapped. There is never a moment without `sessions.jsonl`.
- **Path and identity:** session IDs and provider IDs are checked against the kernel's identity shape before they reach a fact. A value out of shape refuses the import. Attachment paths in queue files must stay under `attachments/` after cleaning, as in 0.1.0.
- **Secrets:** no prompt text, objective text or attachment bytes reach a fact (INV6). The canary test from K2 is rerun over an import of a journal and queue file seeded with a canary string.
- **Resource limits:** the decoders are bounded by the same limits as 0.1.0, and the 24-session window keeps an import far under `MaxOpenSessions`.

## Acceptance

- Fixtures are generated by a small program built against `6172744`'s own `record()` and `saveInputsLocked`. It runs on the Linux runner, and its fixtures are committed with synthetic content only. Shapes covered:
  - cwd after receipt
  - torn tail
  - corrupt line
  - corrupt queue
  - orphan queue
  - missing `DirectoryIdentity`
  - each receipt row
  - a checkpoint
  - a review
  - more than 24 sessions
- **Failing controls:** each decoder rule has a test that fails when the rule is removed. Targeted mutants cover the mapping table, the 24 window, the torn-tail rule, the swap order and the reimport digest rule.
- **Crash test:** at each barrier, on Linux and Mac. The Windows lock test runs on ah-msi.
- **Rollback, then upgrade:** refuses and names `--reimport`. `--reimport` then imports under generation 2, and earlier facts are unchanged.
- **Event log projection change:** a test passes a projection with the right `LastSeq` but wrong contents, and `Append` still judges by the log's own copy. Everything in the K2 suite still passes.
