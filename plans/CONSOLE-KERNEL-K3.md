# K3: legacy import, not wired

Status: revision 2, for plan review round 2. Round 1 (NATIVE, at `bbcf0f6`) blocked on B1–B6. Each blocker's fix is marked below.

This slice implements "Old sessions: one-way import" in [the kernel plan](CONSOLE-KERNEL.md) as a library with tests. Nothing calls it until K10. No real data directory is read or written. Tests use temp directories, and fixtures generated by `6172744` code.

## What 0.1.0 does (read from `6172744`)

- **Journal, `sessions.jsonl`.**
  - Format: one JSON record per line, `Sync` after each.
  - Write limits: 60,000 bytes per record, 8 MiB per file.
  - Open: `O_CREATE` (state.go:226), so 0.1.0 starts on a missing or empty journal.
  - Each record is a full snapshot, and only `state` says what kind of record it is.
- **How `restore()` reads the journal** (journal.go:11-106):
  - Every record with `reviewParent` goes to reviews, whatever its state or window. The last record per session wins.
  - Every record with `taskId` or `checkpoint` also goes to checkpoints. This routing is additive: the record still counts as a session record. The latest checkpoint record per session wins.
  - `checkpoint:*` states are skipped, and so are empty `sessionId` or `providerId`. That drops `admission_failed`, whose provider ID is empty.
  - For each session, the last record wins. A `closed` session is dropped.
  - Only the 24 most recent sessions are kept, by order of first appearance.
  - A `null` line parses to a zero record and is skipped.
- **States `record()` can write:** `created`, `intent`, `accepted`, `rejected`, `unknown`, `paused`, `final`, `review_unknown`, `cwd`, `closed`, `admission_failed`, `checkpoint:*`. No `abandoned` state is ever written.
- **A line 0.1.0 cannot read stops it from starting.** That covers a torn tail, a corrupt line, an empty line, non-JSON, and any line over 64 KiB. So a non-JSON sentinel keeps 0.1.0 out.
- **Lock:** `console.lock`, taken before the journal is read and held for the whole process life. On Unix it is `flock(LOCK_EX|LOCK_NB)`. On Windows it is `LockFileEx` exclusive, byte 0, length 1. The event log takes the same lock the same way.
- **Queue files:** `queued-inputs/<sha256(sessionId)>.json`, plus `.previous`.
  - They are decoded strictly.
  - They are checked against the journal checkpoint.
  - They override its input revision, objective hash and passes (queue_store.go:181-188).
  - Only restored sessions' files are read.
  - 0.1.0 refuses to start on a corrupt queue file, a task mismatch, or an older input revision.

## Scope

1. **Lock and no-write verify (B1).**
   - The event log exports its directory lock as a standalone `LockDir(dir)` that returns a handle.
   - `eventlog.Open` gains a variant, `OpenLocked(ctx, handle, now)`, that adopts an already-held lock.
   - The importer takes the bare lock and decodes, writing nothing. Only after decoding succeeds does it create or open the log.
   - `Verify(dir)` takes the lock, decodes and reports, and writes nothing. A test checks that the directory is byte-identical afterwards (names, sizes, mtimes, contents).
   - Every refusal before commit leaves the directory byte-identical. The same test pattern checks each refusal case.
2. **Decoder.**
   - It is a pure function from the journal's bytes to a typed `Legacy` value. It follows `restore()` exactly, with the corrections above, except that it does not apply the 24 window (see 4).
   - The closed state set is the list above. Any other state refuses the import.
   - A torn final line is one with no trailing newline that does not parse. It is reported.
   - Any other bad line refuses the import.
   - The read limits are 0.1.0's: 8 MiB per file, and 64 KiB per line.
3. **Queue decoder.**
   - A bounded, read-only port of `restoreInputs` and `mergeQueueCandidates`. Only references and hashes leave it.
   - Deliberate change from 0.1.0: a corrupt or mismatched queue file does not refuse. It becomes a per-session `unknown` marker, so the console can still start.
   - Orphan files are listed.
   - An entry with no `DirectoryIdentity` is marked.
   - The mapping uses the queue decoder's input revision, objective hash and passes where the queue overrides the journal, as 0.1.0 does.
4. **Which sessions import (B6).**
   - Every session that is not closed imports, not just 0.1.0's 24.
   - The batch ends with `ProcessRestarted`, whose trim hides old sessions and protects unresolved ones, per table 2.
   - Before commit, the importer refuses if the projection's open sessions plus the imported ones would exceed `MaxOpenSessions`. The refusal changes nothing.
5. **Completeness guard (B6).** The driver refuses to commit if any decoded item has no legal fact kind yet. That covers queue entries, orphan queue files, corrupt-queue markers, and review records. The refusal names the missing kinds and changes nothing.
   - A failing-control test covers each item type.
   - K1c (inputs) and K1d (reviews and checkpoints) add those kinds, and the guard lifts per kind with them.
   - So a real data directory cannot be imported until then. Since K10 wires import only after K1c and K1d, this costs nothing.
6. **Mapping.**
   - One `LegacyImported` per imported session.
     - `final` imports as `final`.
     - `rejected` and `paused` import as `rejected`.
     - `intent`, `accepted` and `unknown` import as `unknown`.
     - A last record with no request (`created`, `cwd`) imports with no receipt.
     - `review_unknown` belongs to reviews and is handled by K1d.
     - The `abandoned` row is kept for K10's synthetic fixtures only, because 0.1.0 never writes it.
   - The import digest is SHA-256 over the full journal bytes, torn tail included, followed by each queue file's path and bytes in sorted order.
   - One `Append` carries every `LegacyImported`, then `LegacyImportCompleted{digest, generation}`, then `ProcessRestarted`.
7. **Kernel row change for generations (B5).**
   - New projection field `LegacyGeneration`, which starts at 0.
   - New fact field `ImportGeneration`, named so it is not confused with the task `Generation`.
   - `LegacyImported` is legal only when its `ImportGeneration == LegacyGeneration + 1`, and illegal at any other time, including after the completion of its generation.
   - `LegacyImportCompleted` needs a nonempty digest different from the current one, with `ImportGeneration == LegacyGeneration + 1`. It sets the digest and `LegacyGeneration`.
   - `Reduce` never parses session IDs. Generation N > 1 uses IDs `<old>:g<N>`, and the importer checks the identity shape before building facts.
   - The separate model agent re-derives these rows from the table before code.
8. **Swap before commit, crash-durable (B2, and the half-migrated window).** Order:
   1. Preflight, writing only one probe file that is then removed. Hard link and rename-over must work in this directory, or the import refuses. FAT and exFAT fail this check.
   2. Write `sessions.jsonl.sentinel-tmp`, fsync it, and close it.
   3. Hard-link `sessions.jsonl` to `sessions.jsonl.imported-<ts>` with an exclusive name, failing if it exists. Fsync the directory.
   4. Rename the sentinel over `sessions.jsonl`. Fsync the directory.
   5. Decode from the `.imported` copy, then `Append`.

   If there is no journal at all, a sentinel is still installed, and the digest covers empty journal bytes plus the queue files. A torn tail is copied, never truncated, into `sessions.jsonl.torn-<ts>`, so the `.imported` file keeps the bytes the digest covers (B3).

   Recovery on open, under the lock:

   | State | Action |
   |---|---|
   | Sentinel, import completed | Done |
   | Sentinel, not completed, exactly one `.imported-*` without a completed digest | Resume at step 5 from that file |
   | Real `sessions.jsonl`, nothing completed | Start at step 1 |
   | Real `sessions.jsonl`, completed, digest differs | Refuse, naming `--reimport` |
   | Real `sessions.jsonl`, completed, same digest | Nothing changed since that import: an interrupted swap, or a rollback that 0.1.0 never changed. A reimport cannot cause this, since it needs a different digest. Reinstall the sentinel |
   | `sessions.jsonl` missing, completed | Reinstall the sentinel |
   | `sessions.jsonl` missing, nothing completed | Install the sentinel and import empty |

   Windows: directory fsync is a no-op, and hard links need NTFS. The preflight enforces that.
9. **Rollback (B4).**
   - Refuses unless `sessions.jsonl` is byte-exactly the sentinel.
   - Selects the `.imported-*` whose digest equals the projection's `LegacyImported`, not the newest by name.
   - Installs it by hard link to a temp name, fsync, then rename over the sentinel, so the `.imported` copy survives.
   - A torn tail in that file is stripped in the restored copy only, so 0.1.0 can start on it. The docs say so.
   - Tests cover both refusals and a double rollback.
10. **`--reimport`.** After a rollback, it runs the same pipeline at generation `LegacyGeneration + 1` with suffixed IDs. Earlier sessions stay read-only and unchanged.
11. **Event log holds its own projection (the N1 TODO).**
    - `Log` keeps the projection it last published, including replay quarantines and the in-memory restart of a latched open.
    - `Append` checks the caller's `LastSeq` and judges against its own copy.
    - The copy advances from the decoded stored facts, and only after a successful new commit. It does not advance on a replayed receipt or on any error.
    - `Append` also returns the new projection.
    - The full K2 suite is rerun, including the race run.

## Risks and negative cases

- **Malformed data:**
  - torn tail
  - corrupt line, empty line or `null` line
  - a line over 64 KiB or a file over 8 MiB
  - an unknown state
  - unknown or duplicate queue keys, a queue file with only `.previous`, or a `.previous` that disagrees
  - objective hash mismatch, task mismatch, older revision

  Each case has an expected outcome. Each refusal leaves the directory byte-identical.
- **Concurrency:** a held lock refuses with nothing changed. Tests cover a real second process on Linux, Mac and Windows.
- **Crash ordering:** `kill -9` cannot falsify fsync order. Two checks cover it:
  - A filesystem seam records the sequence of create, write, fsync, link, rename and directory-fsync calls. A test asserts the exact order.
  - A child killed at each barrier, then reopened, must land in a row of the recovery table.
- **Secrets (INV6):** no prompt, objective or attachment bytes reach a fact. The K2 canary is rerun over an import seeded with a canary in text, objective and attachment.
- **Version:** `Verify` reports any state, field or queue shape outside the `6172744` set before a real import.

## Acceptance

- **Fixtures** come from a program built against `6172744`'s `record()` and `saveInputsLocked`. It runs on the Linux runner. The fixtures use synthetic content and are committed. Shapes covered:
  - every state above
  - cwd after receipt
  - torn tail
  - a corrupt line
  - a corrupt queue file
  - an orphan queue file
  - a missing `DirectoryIdentity`
  - a checkpoint with additive routing
  - a review
  - more than 24 sessions
  - a missing journal
- **Failing controls:** targeted mutants cover the mapping, the completeness guard, the open-session check, swap order, rollback selection, the generation rule, and projection advancement.
- **Cross-platform:** the crash and ordering tests run on Linux and Mac. The lock and preflight tests run on Windows (ah-msi).
- **Rollback, then upgrade:** an upgrade after rollback refuses and names `--reimport`. A reimport commits at generation 2.
- **Review:** plan review round 2 before code. Then code inspection under the same stop rules.
