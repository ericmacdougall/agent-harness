fix(desktop): end capture on revocation even when the page resists

Why: delta red-team BLOCK on PR 1309 (F1, material privacy): freshDocument() did loadURL(getURL()).catch(() => {}) (silent) and treated it as success. A beforeunload handler, a 204, an attachment or a GET that never answers left the old document live, with its camera track and staged inputs, on the tab handed to the person, while t.media=false already said capture ended.
What: the revocation load now overrides will-prevent-unload for its duration only (removed on every path), is bounded at 1.5 s per step, and without a committed new document calls stop() and loads about:blank. The media indicator stays on until a document commits (did-navigate); mediaGrants still end at once. Every failure logs revoke_failed with the tab id, a fixed reason and a Chromium error code. If about:blank fails too, a hidden tab closes (revoke_failed) and a visible one stays with the person showing capture and revocation=failed in state and the toolbar. Applies to renew drop and narrowing, park, stop(), stopTab() and dropAgentTab. Adds real-Electron fake-camera tests through the built host (control, beforeunload, 204, attachment, hung GET, stop and renew paths) and unit tests for the fallback, the override lifetime, the indicator and the logs.
Testing: `cd apps/desktop && pnpm run build && xvfb-run -a npx vitest run src/agent-browser/revocation-capture.test.ts src/agent-browser/reload-post.test.ts` -> 7 passed (on 73b08aed: 5 of 6 new failed, control passed); `npx vitest run src/agent-browser/host.test.ts` -> 252 passed (on the old host.ts: the 16 new tests failed, 236 passed); `npx vitest run src/agent-browser src/ctl` -> 632 passed, 13 failed (pre-existing files.test.ts x11, capture-return-recovery x2), 7 skipped without a display; `npx tsc --noEmit` clean.
Refs: GoodQA #15477
Risk: a page whose document cannot be replaced at all now shows capture on and a failed revocation instead of a silent false "ended"; stop()/stopTab() on a person tab can land on about:blank where the GET is refused or empty.
