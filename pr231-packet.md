## Outcome
In a shared original checkout (the main working tree, whose `.git` is a directory) that has uncommitted changes, an agent shell that stages or commits EVERYTHING (`git add -A`, `--all`, `.`, `:/`, `-u`, `git commit -a`, or a commit with a whole-tree pathspec) gets a `bulk_staging` finding that names the sanctioned form (stage explicit paths, or work in your own linked worktree). This stops one session sweeping another session's uncommitted changes into its commit. It is a WARN by default (decision D2, labelled below) and a block when the policy sets `modes.bulk_staging` to enforce.

## Design (read command_guard.py bulk_staging)
- Target: the directory the command acts on (the cwd after `cd`, each `-C`, `--work-tree`, `--git-dir`, `GIT_WORK_TREE`, `GIT_DIR`), then `_original_checkout_top` walks up to the nearest `.git`: a directory means the original checkout (judged), a `.git` file means a linked worktree or submodule (left alone), nothing means not a checkout.
- Forms: `_bulk_add_form` for `git add` and `git stage`: -A, --all, -u, --update, --no-ignore-removal (git's unambiguous abbreviations included) are bulk only with no pathspec or with a whole-tree pathspec (`git add -A sub/` stages only sub/); an interactive selection (-p, -i, -e) is an explicit choice. `_bulk_commit_form` for `git commit`: -a or --all, also inside a short cluster (`-am`, `-sa`), a whole-tree pathspec (`git commit -m x .`); the text of -m, -F and the other value options is not read as a flag (`-ma` is the message `a`; --gpg-sign and -S take only an attached value). `_bulk_pathspecs`: any whole-tree pathspec (`.`, `./`, `sub/..`, `:/`, `:(top)`, bare globs `*` and `**`, `:(top)*`, `:/**`, `:(icase)*`, or a path that is the repository top or contains it, such as `..`), or a list made only of exclusions (`':!x'`, `':^x'`, `':(exclude)x'`, which git reads as everything else). `sub/.` and `./sub/file` are explicit. `_bulk_alias_form`: an alias defined with `-c alias.NAME=...` and invoked is judged on its expansion; a `!` alias is searched for every `git ... add|stage|commit WORDS`, however quoted or nested in `sh -c`.
- Dirty check: the existing hardened `_git_try(top, ['status', '--porcelain=v1', '-z', '--untracked-files=normal'], 2.0)` (fsmonitor off, hooks off, sanitized environment); a clean tree reports nothing; a failure, a timeout or a path that is not a repository reports nothing and never raises (fail open, accident prevention).
- Mode: `bulk_staging` is a new category (default warn, switchable to enforce in the policy file like broad_kill); the other categories keep their modes.
