- F1 (Medium, security): the calling session was read through `_session_env_of`, whose `ps eww -o command=` output starts with the parent's command line, so `zsh -c 'CLAUDE_CODE_SESSION_ID=<other> ah clone-remove ...'` matched the inline override and passed the equality check. Now `clone_remove.parent_session_env(os.getppid())` reads ONLY the parent's real environment: `process_environment()` uses sysctl KERN_PROCARGS2 through ctypes on macOS (`parse_procargs2()` separates argc, the executable path, the argv strings and then the environment strings) and /proc/PID/environ on Linux; the variable must appear exactly once, non-empty; absent, empty, duplicated or unreadable reads as None and `ah` refuses. `ah.py` no longer calls `_session_env_of` for this command. UNMOCKED tests (ParentEnvironment): real child processes whose command line carries `CLAUDE_CODE_SESSION_ID=OTHER` while the environment holds REAL (reads REAL) or nothing (reads None); a missing pid, duplicate and empty variable read as None; a crafted KERN_PROCARGS2 buffer whose argv holds one value and environment another; and an end-to-end test where a real parent process (environment REAL, command line with the override) runs the real `ah.py clone-remove` with the inline override in the child's environment, and the command refuses with a session message, for a parent with a different value and for a parent with no variable. Mutants (31 of 31 caught by `python3 -B tests/mutants_clone_remove.py`): `ah.py` back on the `ps` reader (caught by the end-to-end test), a duplicate variable accepted, arguments parsed as environment.
- F2 (Low): `read_dirs` refuses with a CloneError ("the intent row carries no verified directory set") when the row has no `dirs_sha256` or `dirs_count`; `resume_clone` reads them with `.get()`. Test: a stripped intent row refuses with that message; mutant: the guard removed.
