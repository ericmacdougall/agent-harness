## Outcome
A merged hook file can be installed on a remote host (t2-dev, ah-mac-mini) through one audited command instead of a hand-typed cp, mv or scp into a guarded path (the 2026-11-11 t2-dev install of command_guard.py was blocked as a remote cp and then done with scp, a second route around a guard). The Mac guard allows the command only in its exact literal form (installed ah.py, the install flag grammar) and only for main; that rule is accident prevention, not an access control.

## Design (read ah_install.py)
- Source proof (`fetch_source`): nothing is read from a repository the caller names. The canonical main (constant CANONICAL_URL) is fetched into a FRESH bare repository for each run (new directory 0700 under ~/.agent-harness/install-cache, fsckObjects on, commit graph off, replace objects off, grafts and shallow refused); REF must be an ancestor of the fetched main; the commit, every tree on the path and the blob are re-hashed here (git does not hash-check on read); the blob mode must be 100644 or 100755; names only from the HOOKS tuple at that commit, read with ast; an ancestor with a newer merged version of a requested file is a DOWNGRADE and refuses unless --allow-older (audited).
- Remote program: REMOTE_SCRIPT is constant text (python 3.9 compatible), run as ONE shell-quoted command through `ssh -o BatchMode=yes -o ClearAllForwardings=yes -- HOST CMD`; ops probe, lock, unlock, stage, commit, restore, read_backup, selftest, audit, prune, cleanup. Every path comes from the fixed hooks directory plus a name matched by regex; the hooks directory must be a real directory owned by the user; temporary files are created O_EXCL|O_NOFOLLOW; replace is os.replace in the same directory.
- Flow (`_run`): validate, fetch and prove, probe the host, take the self-test BASELINE (the guard must already deny the rm -rf ~/.claude/wals probe and allow ls -la), write the Mac start row (fsynced; a failed write stops before any ssh write, exit 3), lock, phase 1 stage and verify every file and back up each old file on the host and on the Mac (sha-checked), phase 2 commit in a fixed order with command_guard.py LAST, read every sha back, self-test again; a changed probe verdict, a new failing doctor check or a failed read-back rolls every file back (guard first). Unknown outcome (lost answer after the first live write, an unexpected error, an interrupted rollback) is never reported as installed or refused. A host with an unfinished run refuses new runs; `--resume` reuses the ORIGINAL baseline; `--rollback RUN` restores from backups only when the live sha still equals the run's new sha (else --force-file, audited) and is never blocked by the self-test.
- Guard rule (`install_files_refusal` in command_guard.py, called from hook_main): quotes removed before matching, quote-aware command split, bash/sh/zsh -c bodies inspected, env/sudo wrappers looked through, a python import of ah_install refused for every caller, redirections and viewer programs (grep, rg, git, sed...) pass, the installed ah.py literal form and the install flag grammar only, main only (caller_identity.is_main from the hook payload).

Highest-risk cases and their tests: bytes that are not the merged commit (Source tests: unmerged ref, forged object after the fetch, replace ref, symlink blob, fork URL, planted pack ignored), a half-installed host (two-phase install, a bad file two with the guard first changes nothing live, the unfinished-run refusal, resume with the original baseline), a broken guard reaching the host (allow-all guard, crashing guard, a probe that stops blocking, a baseline that already fails open, genuinely broken guards installed from a test commit and rolled back with every live sha restored), a rollback undoing a later install, the guard rule being bypassed (quote split, bash -c, env wrapper, heredoc and concatenated imports, worktree copy, script named ah on PATH) and false positives on everyday commands (commit messages with a semicolon, grep and rg, npm and pip install). The remote script is run through a real shell in every test against the REAL command_guard.py and doctor.py in a temporary host HOME.

## Disclosed limits
The real ssh-to-localhost test skips on the author machine (ssh to localhost needs a key there; the owner did not change authorized_keys); the real proof on t2-dev and ah-mac-mini is AC-10, for main. The guard rule cannot see a script that imports ah_install through sys.path or any program that speaks ssh itself. The proof reads commits between REF and main through the fresh fetch without re-hashing each one. The after-test runs the newly installed doctor.py when it is part of the run.

Risk and rollback: revert the commit; nothing else depends on it. A remote overwrite of hook files is protected by backups on both ends, an atomic rename, read-back, the host self-test and automatic rollback; a lost connection leaves the host refusing new runs until a resume or rollback.
