## The remote-auth fix (new in this delta)
Diagnosis. `REMOTE_LS` runs under `cg._clone_env()`, which sets `GIT_CONFIG_GLOBAL=/dev/null` so no program from config can run; that also removes the account's credential helper, so a private https remote can never answer, whatever `--remote-auth` says (the flag only kept `SSH_AUTH_SOCK`, which an https remote does not use). Reproduced with the same code path against a PRIVATE repository of the owner (not wt-pp768, not the clone's own remote): `REMOTE_LS(url, repo, 60, authenticated=False)` and `authenticated=True` both failed with ValueError. A public repository answered in both modes (agent-harness is public: 284 refs, 215 pull heads).
Fix. New `remote_ls_argv(repo, url, authenticated)`: with `--remote-auth` ONLY it adds `-c credential.helper=` (clears any other helper) and `-c credential.https://github.com.helper=!<gh> auth git-credential`, where `<gh>` is resolved with `shutil.which('gh', path=<the sanitized PATH>)`; no helper when `gh` is missing; none for the anonymous listing. The token goes from the helper to git, never through argv, output, the audit or this tool. Everything else on the command is unchanged (`protocol.allow=never` with only the https and ssh overrides on this one call, no hooks, no fsmonitor).
LIVE private-repo proof after the fix, same code path, from a real Claude Code Bash call, counts only: `REMOTE_LS(<private repo url>, repo, 60, authenticated=True)` returned 35 refs; `authenticated=False` still failed. The anonymous listing of a private repository must keep failing, so this is the intended behaviour.
Tests: `RemoteAuth` in tests/test_ah_clone_remove_review.py: the authenticated argv names exactly one host-scoped helper and clears the others, the anonymous argv names none, neither carries a token or password word, `gh` missing degrades to no helper, the real `REMOTE_LS` passes the helper through to the subprocess call (fake subprocess, real function). Mutants (34 of 34 caught by `python3 -B tests/mutants_clone_remove.py`): remote-auth passes no helper, helper not scoped to the host, plus all earlier ones.

## Stated limitation (unchanged, PENDING user acceptance, ask wb37184efe71)
The session identity is caller-settable: a forged `CLAUDE_CODE_SESSION_ID=OTHER ah clone-remove ...` can reach the verified-clean, fully pushed `receipts/wt-*` clone of another existing session. With the unimplemented live-owner refusal (D8) it disrupts that session (a local clone it may be using, recreatable by `git clone`); it loses no work that a ref, a reflog or the live remote holds, with the exceptions named in spec AC-4: (a) commits no ref or reflog reaches, (b) local repository state outside history (config, info/exclude, COMMIT_EDITMSG, reflog messages and timestamps), (c) build directories presumed regenerable by name only, (d) pushed means on the live remote at verification time, (e) a single file moved in whole, a directory created during the set walk, inode reuse. Pinned by `test_an_untrusted_home_is_refused_and_the_forged_session_limit_is_real`.

Risk and rollback: revert the commit (the earlier head cannot verify a private remote, so rolling back leaves the tool unusable for private repositories).
