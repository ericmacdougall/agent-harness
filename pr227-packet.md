## Outcome
A critical alert that a script writes to the local ring with `ops_watch.py emit` (fabric:live-down:fabd from fabd-health.sh) now reaches the GoodQA alert digest and the deadman mail, and its clear reaches the digest. Before this, `persist()` in `run_once` was the only writer of `pending_comment` and `pending_deadman` and queued only ops-watch's own transitions, so the alert appeared only in the local ring, `ops_watch status`, the peer `active.json` and the context injection (the feed whose "high line among 72" hid a 15.5 hour Fabric outage).

## Design (read ops_watch.py forward_foreign and queue_events)
- `queue_events(cfg, state, news, now)` is the queue code that was inside `persist()`, now shared: digest queue for every row, deadman queue for critical raises at most once per key per 6 hours, none when no deadman sink is configured.
- `forward_foreign(cfg, home, state, ring, now)` runs once per `run_once`, after the first `persist`. It reads the ring and returns the rows to queue: source other than `ops-watch`, this host (`ring_host`), severity critical for a raise, a clear only for a key forwarded as raised (state `fwd_active`, capped at 200), text refreshes (`detail.updated`, `detail.reasserted`) skipped. State `fwd_seq` is the highest ring seq seen.
- The first run (no `fwd_seq`) or a ring whose top seq is below the stored one (recreated ring) forwards only what is standing now (the latest row per key is a critical raise) and the clear that the old sequence never delivered; it never replays history.
- The queues and `fwd_seq` are written in one `save_state`: a crash before it re-forwards (at-least-once), never loses. A malformed foreign row (a non-object `detail`, a non-string key or source) is read as an empty detail or skipped; it never stops the alert path and `fwd_seq` always advances.
