Follow-up to goodqa#15743 (ah clone-remove, PR 215), option C from the session-identity decision.

Problem. ah clone-remove takes the caller's session from CLAUDE_CODE_SESSION_ID in the command's own environment and checks only that the session's WAL and work directories exist. That value is caller-settable: `CLAUDE_CODE_SESSION_ID=OTHER ah clone-remove ...` (also through any wrapper shell) names another existing session. A real tool call was measured on this Mac: the harness adds the variable to the command after the tool shell started, so no ancestor process carries it in its start environment (the python process had it, the tool shell, the claude process, the login shell and Terminal did not); reading ancestors cannot prove identity.

Impact. Bounded by the tool's own checks: the target must be a verified-clean, fully pushed receipts/wt-* clone of the named session (no stash, no unpushed ref or reflog commit, no untracked file, ignored files only as whole regenerable build directories, no process or open file inside). What could be lost: nothing committed or pushed. What is disrupted: the other session loses a local clone it may be using (recreatable by `git clone`), and an idle owner of that clone gets no warning because the live-owner refusal (spec decision D8) is not built. Names of things that could still be lost: ignored build output (regenerable) and a file the clone's owner writes in the instant between verification and the walk (kept by the ctime and directory-set rules, so reported, not deleted).

Proposed fix (option C). A hook-written per-session token that ah verifies: the PreToolUse hook of the Claude Code process writes, for each tool call, a short-lived single-use stamp keyed by the real session and the command, in a directory a sub-agent cannot forge, and ah clone-remove takes the session from the verified stamp, not from the environment (the same pattern as the main-only stamps in caller_identity.py). Acceptance: a forged CLAUDE_CODE_SESSION_ID, with or without a wrapper shell, is refused; a legitimate call from a real tool shell passes; tests run unmocked against a real stamp directory; the unused KERN_PROCARGS2 reader in clone_remove.py is removed or used.

Related: ah owners rows expose no worktree or cwd, so the live-owner refusal in the spec (AC-4, D8) cannot be built; a follow-up there would let clone-remove refuse while another owner uses the target.
