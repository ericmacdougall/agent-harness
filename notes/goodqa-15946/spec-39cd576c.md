## Outcome

Main can run `ah lane new/start/bind/checkpoint/refresh/status/verify` and `resolve-ledger` and get a durable, hash-chained, per-owner-lane store with a canonical repository identity, a stable stream key and a versioned, canary-able kit, without any change to review, evidence, click-test, sign-off or done state.

## Scope

- In: build-spec section 3 (slice S1): `lane` package with identity, store, manifest, kit (renderer, lint, redaction, kit_version knob), sources, gates G1 to G3, commands, an ops-watch check module that reads snapshots only, and advisory spawn-hook text. Delivered in order: (1) a read-only ticket-attachment write-path check (C-2), (2) identity.py, store.py and the kit_version knob (AC-2, the store part of AC-4, AC-43), (3) the remaining commands. A later PR of the same slice may carry (3); each PR states which ACs it verifies and the rest stay open, never reported as done.
- Out: the `Live-target:` spec header (SG; applies once SG is live, verified manifest-only here, C-4); gates G4 to G11, `route`, `close`, `recover`, `adopt`, budgets, click-test plan generation (S2 to S7); owner cap enforcement in the spawn hook (SC); `supersedes` (S3); the install itself (main lands and installs the change; AC-44 is the live check performed on the installed build, and the slice is not done until it passes).
- Topology: the lane store is host-local (one store per OS user per host); uniqueness of one open lane per ticket and repository holds inside one store. Cross-host uniqueness is not claimed: lane commands run on main's host, and the other install host is exercised only by the AC-44 disposable lane against its own store. `local:DEVICE:INODE` identities are valid only inside one host's store, and the manifest records the fleet alias of the host. The escalation ledger rung for a stream key is also per host: a rung earned on one host does not carry to the other.
- Disclosed limitation (cap): until SC ships, the spawn hook is warn-only, so a direct owner spawn can race a lane reservation; S1 never creates an owner (main spawns), counts reservations conservatively, prints that direct-spawn enforcement is not live, and `bind` refuses a bind that would pass the cap. Making admission atomic for direct spawns is SC's job (AC-49), not S1's.
- Layout note: the build spec writes `hooks/lane/...` and `hooks/tests/lane/`; in the checkout the real paths are `harness/hooks/lane/...` and `tests/` (existing convention). Module names are unchanged.

## Live check and rollback

AC-44 is the live check: installed on the Mac and t2-dev at one landed commit, exercised on a disposable lane, `REALLY_TESTED` per host with the commit. Rollback: the installer at the pre-S1 commit; the lane store stays in place and is never removed. Compatibility: S1 introduces the `lane` package and `lane.manifest/1`; the commit before S1 has no lane reader at all, so rolling back to it leaves the store untouched and unread (nothing parses it and nothing is lost), the installer does not remove files outside its inventory and no hook registration points at the lane. Later builds read this store through the manifest rules (an unknown field or higher schema parks the lane as `newer schema, unreadable`); any later change to `lane.manifest/1` needs a numbered revision with a migration test. Until AC-44 passes the slice is reported landed-not-live, never done.

## Risks

- Scope overrun of a very large slice: ship in ordered PRs, each stating the ACs it verifies; report the rest as open, never as done.
- Concurrency and multi-store ordering (store lock, op records): op-record retry tests and barrier tests with bounded probes.
- A wrong owner-count predicate would silently exceed the cap: parity test against the hook's predicate with a mutation.
- Ticket-attachment write path may not work from `new`: first task is a read-only check; if it fails S1 stops and reports.
- Template or generator drift by a same-user agent: stated limit, ticket-anchored digests detect it.
- Layout assumption (harness/hooks and tests/ instead of hooks/lane): recorded as a deviation in Scope.
