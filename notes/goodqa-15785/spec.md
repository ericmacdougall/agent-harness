# Spec: command_guard: block reads of GoodQA user-token and gq-browser key files

Ticket: GoodQA goodqa#15785
Author: agent:af9e33704216a1ea1 (claude-sonnet-5-5)
Click-test: not-applicable (a command-text guard rule with no UI; the proof is the real guard decision on the commands in the tests)
Sign-off: main
Review-policy: standard

## Outcome

An agent shell can no longer print the user's GoodQA user token (`~/.config/goodqa/user-token`, which acts as the user) or a minted gq-browser lease key (`~/.agent-harness/gq-browser/16-hex/key`, valid for up to 24 hours) into a transcript. One command line is refused when it reads either file by name or glob; walks a directory that holds one (a recursive search, an archive or copy tool, a `find -exec` reader, a search with no path run from that directory or an ancestor); feeds a reader a list of names that another part of the same command line prints; or carries the path inside an option value or a command run from an option value. When the guard cannot finish its analysis (an internal error, a budget stop, nesting too deep, oversized input, a crash or timeout of the analyser), a command naming a credential location is refused, never allowed. The gq-browser client keeps reading the files in-process.

## Scope

- In: harness/hooks/command_guard.py: the two credential regexes and samples; the policy list `credential_parent_dirs`; per-tool option tables and getopt walks (the grep family with ugrep, rg, ag, ack, pt; tar, bsdtar, gtar, pax; curl, wget, scp, rsync, sftp, ditto, zip, 7z, xargs, parallel); tar mode readings, `-C` bases and the names-file table; destination proofs for copy, fetch and archive tools; values derived from inside words; commands run from option values; find start directories, `-exec` bodies and `-files0-from`; name-list producers and readers within one command line; brace sequence expressions and brace words past the expansion cap; the raw-text credential fallback `CRED_TEXT` in command_guard.py, with its identical copy in harness/hooks/command_guard_hook.py. Tests: tests/test_command_guard_gq_credentials.py and tests/mutants_gq_credentials.py. The docs line in docs/gq-browser.md and the AC-8 pin in tests/test_gq_browser.py belong to agent-harness PR 220.
- Which credentials each rule covers (verdicts probed at the head and pinned in AC-11 and NEG-9):
  - Every credential file (`credential_path_regexes` and `credential_samples`, through `_cred_one`), including `~/.ssh` and `~/.aws` keys: the name and glob rule, values inside words, `find -exec` start directories, name lists, brace words past the cap, `-files0-from` lists.
  - Every credential directory (`credential_dirs`, such as `~/.ssh` and `~/.aws`, through `under_cred_dir`): recursive searches of the directory or an ancestor, `find -exec` readers, and name-list producers.
  - The two GoodQA parents only (`credential_parent_dirs`, through `under_cred_parent`): an archive, compressor or copy tool given the directory or an ancestor, a recursive search with no path judged on the working directory, and a key directory inside gq-browser. `tar -cf - ~/.ssh`, `zip -r - ~/.aws`, `scp -r ~/.ssh host:` and `cd ~/.ssh && grep -r .` therefore stay allowed. This is a stated limit, followed up in GoodQA goodqa#15886.
- Out: multi-step flows need cross-step taint tracking, followed up in GoodQA goodqa#15885. These are: a credential copied to a file or variable and read by a later command (`cp TOKEN /tmp/t` then `cat /tmp/t`; `export TOK=$(cat TOKEN)` then `echo $TOK`); a name list written to a file and read later (`find DIR -fprint LIST` or `find DIR > LIST`, then `tar -T LIST`, `bsdtar -I LIST` or `xargs -a LIST cat`); arrays filled by `mapfile` or `readarray` (`mapfile -t F < <(find DIR -type f); cat "${F[@]}"`, even within one line); and a symlink to a credential directory made earlier and walked later. Also out: a program that reads the file itself (`python3 -c` with `os.walk`, a script on disk), since the guard sees command text only and is accident prevention, not an access control; other GoodQA files; changing the refusal text or the secret_dump mode.
- Obfuscated path forms are IN scope where the guard models the shell's own expansion, and these are pinned refused: ANSI-C quoting (`goodq$'\x61'`), `~user`, `/proc/self/cwd/...`, `.`, `..` and `//` segments, `$HOME` and `${HOME}`, quotes and backslashes inside a word, brace lists and sequences of any size, globs, and an existing symlink to the token or a key file (resolved by the name rule). OUT of scope: a path assembled in variables across commands, a decoded encoding (`base64 -d`, `printf %b`) whose output names the path, and a symlink to a credential directory (multi-step, goodqa#15885).

## Acceptance criteria

Invariant (fail closed): a word is exempt from the credential rules only when a rule proves it is not read; any internal error, RecursionError, node or time budget stop, nesting past max_depth, oversized command, unterminated quote, hook alarm, analyser crash or brace expansion past its cap, on a command that names a credential location, yields a refusal, never allow and never only a warning.

The spec_flow lint accepts only numbered criteria (`AC-` and a number), so the split of the former AC-1 is AC-1 to AC-9. Every refusal below carries a secret_dump rule, and the tests assert the rule id, not only the verdict.

- AC-3: a search is read the way the tool reads it. A getopt walk with a per-tool option table (grep as the union of GNU grep, BSD grep and ugrep 7; rg; ag; ack) consumes the value of a recognised option, separate or attached (`-etok`, `-rnA3`, `--regexp=PAT`). It takes the first free word as the pattern unless an option gave one, and reads count-only letters and long names (each tool's own: rg `-L` is --follow) only from option letters, never from a value (`grep -ec FILE` prints). Recursion is recognised as `-r`, `-R`, `--recursive`, `--dereference-recursive`, `-d recurse` and every getopt abbreviation of these; rg, ag, ack and pt are always recursive. The search becomes UNCERTAIN, and fails closed, when any of these is present: an option the table does not know, an abbreviation such as `--group`, an optional-valued option without `=`, a ugrep letter whose arity differs between implementations (`-X -J -M -O -Z`), pt (no table), or options that may come from outside the command line (TAR_OPTIONS, GREP_OPTIONS, RIPGREP_CONFIG_PATH, ACK_OPTIONS, ACKRC, an .ackrc in the working directory or any parent, /etc/ackrc, ~/.ackrc, ~/.config/ack/ackrc). Then every free word is judged, and a recursive search is also judged on the working directory whatever its operands. A file a search opens as an option value (`grep -f FILE`, `--file=FILE`, rg `--ignore-file`, ugrep `-f` under GREP_PATH) is judged by name, and count-only exempts only the searched operands. - AC-4: tar takes the most dangerous reading. Create mode is read from the maximal reading: letters stop only at a value letter of every tar (C f T X); every word counts; and any abbreviation of a long create, append, update, catenate or delete option counts. Extract or list mode is read from the minimal reading: letters stop at a value letter of any tar, and a word that may be the previous option's value never counts. Operands are skipped only when the minimal reading shows read and no reading shows create. An old-style first word that is not all letters, or a letter no known tar accepts, puts the mode in doubt, and then nothing is skipped. A names file is any reading's `-T`, bsdtar `-I` (bsdtar(1): "Synonym for -T"; macOS /usr/bin/tar is bsdtar) or `--files-from` in any abbreviation, separate, attached (`-T-`, `-I/dev/stdin`), bundled (`-cI - -f -`) or old style (`cfI - -`), outside extract and list mode. Plain `tar` takes both readings: its `-I` is a names file and also GNU's compress command. gtar `-I` is GNU's compress command only, and bsdtar has no short compress option. - AC-9: fail closed. ## Risks

- Text-guard limits, the same as for the existing credential files:
  - a program reads the file itself (`python3 -c` with `os.walk`, a script on disk);
  - a multi-step flow (Scope: Out, GoodQA goodqa#15885);
  - a glob inside a key directory whose 16-hex name the agent already knows (`cat ~/.agent-harness/gq-browser/0123456789abcdef/*`): the name rule matches the key only by its full name or a glob that the key sample satisfies.
  `ls ~/.agent-harness/gq-browser/*` stays allowed. These are the only forms this spec leaves open within one command line: the pipeline, `$(..)`, `<(..)`, here-string, heredoc and loop forms of a name list are refused (AC-8).
- The older credential directories (`~/.ssh`, `~/.aws` and the rest of `credential_dirs`) do not get the archive, copy or working-directory rules (Scope; NEG-9; GoodQA goodqa#15886). `cd - && rg tok` is allowed because the previous directory is unknown. A no-path `rg`, `ag` or `ack` that is not first in a pipeline reads its input and is not judged, while GNU `grep -r` with no path walks the working directory even with a pipe, and is judged everywhere.
- False refusals the new rules cause, with the remedy for each:
  - (a) A copy or fetch tool loses the destination exemption when its table does not know an option. `wget --some-opt -P ~ URL` and `curl --unknown --output-dir ~ -O URL` are refused, because home is an ancestor of the GoodQA parents. Remedy: drop the option, or name a destination below a project directory (`-P ~/proj/dl`). The tables follow current curl, wget, rsync and scp option lists (`rsync --info=progress2` and `scp -o X=Y` are known and stay allowed), and a new tool option needs a table entry.
  - (b) A search option source outside the command line makes every rg, grep or ack search uncertain. This happens when RIPGREP_CONFIG_PATH, GREP_OPTIONS, ACK_OPTIONS or ACKRC is set in the inherited environment or the command, or an `.ackrc` exists in the working directory, any parent or home. Then a recursive search from home, `~/.config`, `~/.agent-harness` or `/` is refused whatever its operands, and a count-only search of a credential directory is refused. Remedy: run the search from the project directory, where an uncertain search naming project paths stays allowed.
  - (c) A plain `rg foo` or `grep -r foo` with no path, run from home, is refused on purpose: it walks the token's parent. Remedy: `cd` to the project, or name the path.
  - (d) pt has no option table and is always uncertain, so `cd ~ && pt foo /tmp` is refused. Remedy: as in (b).
  - (e) Fail-closed over-blocks from earlier rounds (receipt r4 F1). From home, `~/.config`, `~/.agent-harness` or `/`, a recursive search with an option the tables do not know is refused even when it names a harmless path. A tar whose mode is in doubt skips nothing, so its `-C ~` is judged as a source. Remedy: as in (b), or give tar an explicit mode letter.
  - (f) The raw-text fallback refuses when the analysis fails (an error, budget, nesting, size or crash) on any command whose text names a credential location (AC-9). This includes a URL path segment `/goodqa/` and a glob under `~/.config`. Remedy: split the command into smaller ones.
  - (g) A brace word past 256 alternatives is judged as one glob, so `cat ~/{1..300}` is refused (its glob `~/*` may name `~/.netrc`). Remedy: narrow the expansion or list the files.
  - (h) Unchanged from origin/main: `rsync -e 'ssh -i ~/.ssh/KEY'` and `scp -i ~/.ssh/KEY` are refused, because the key path is a credential word. Remedy: put the IdentityFile in `~/.ssh/config` and use the host alias.
- Measured false-refusal surface: the guard's own corpus (`tests/test_command_guard.py`, its NEGATIVE rows) and the r4 to r7 neighbour lists pass unchanged. No sample of real agent commands was replayed, because transcripts may hold secrets that a replay would print. That is a disclosed limit; the closest proof is the corpus.
- A false refusal of a legitimate command naming the file. Mitigation: the regexes anchor the exact file names, and the neighbour cases are pinned (AC-10, NEG-2, NEG-5, NEG-6, NEG-8).
