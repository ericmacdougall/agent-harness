Follow-up to goodqa#15759 (scp and rsync to a remote harness path), found by the Opus and Sonnet reviews. Measured against the real command_guard.py: a LOCAL recursive copy or sync INTO a directory that contains protected harness files is allowed, for example `cp -r hooks/. ~/.claude/hooks/` and `rsync -av ./hooks/ ~/.claude/hooks/`; one command overwrites command_guard.py and every other hook. goodqa#15759 refuses the REMOTE equivalents (a recursive scp or rsync, or an rsync --delete, whose remote destination contains protected files) but leaves the local rule unchanged because it is used by every session and the change needs its own review.

Proposal: refuse a recursive copy or sync (cp -r, cp -R, cp -a, rsync -r or -a or a trailing-slash source, install -D with several sources) whose local destination is, or contains, a protected directory (hooks, WALs, state), with a refusal that names `ah install-files` for hook files; a copy of a single non-protected file into the hooks directory stays allowed as today. Acceptance: the four spellings above and their `~eric`, `$HOME` and absolute forms are blocked; `cp x ~/.claude/hooks/` and a recursive copy into a project directory stay allowed; tests drive `command_guard.py check` and the hook entry; a failing-first mutant removes the rule.
