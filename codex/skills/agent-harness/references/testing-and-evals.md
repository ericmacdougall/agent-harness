# Testing and eval decisions

Choose the smallest proof that would catch a plausible defect, then widen to cross-boundary failures where risk warrants it. For changed behavior, require an observable before/after failure or controlled mutation and a nonvacuous assertion. Use deterministic seeds and record them. Include malformed, old, future, and missing data; concurrency and stale state; Unicode, time zones and precision; idempotency and restart; auth/tenant boundaries; untrusted files and URLs; resource limits; logging redaction; keyboard/focus/contrast; and safe errors where relevant to the feature. Avoid a boilerplate matrix unrelated to the change.

For forms and queued actions, test delayed responses, double submit, editing while pending, cancel or Escape after confirm, lost response and retry, and a draft reverted to the same normalized payload. Specify disabling, clearing, and idempotency behavior. For a runnable UI or service, the tester must use the real instance and record observed browser/API steps, screenshots or response evidence, account seeding/cleanup, and failures. A fixer changes the owner branch; tester reruns failed flows and a nearby regression. Do not claim click coverage from unit tests alone.

For stochastic, ML, retrieval, or classification changes, use representative held-out and edge sets, synthetic mutations and golden records with provenance, leakage checks, and predefined pass gates. Report sample size and Wilson lower bound for binomial success metrics. Track Cohen's kappa when human labels have agreement data; use paired McNemar analysis for binary decisions on the same cases before and after a change. Do not apply these statistics to deterministic software tests or treat synthetic cases as representative traffic.

For production delivery, add CI, staging rehearsal, migration and backup/restore checks, feature flags, canary, metrics and rollback criteria only where the deployment supports them. Performance claims need representative workload, baseline, hardware, target, and measured result. Stop expensive or nondeterministic experiments after a bounded inconclusive attempt and disclose the limit.
