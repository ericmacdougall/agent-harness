- shell_words (goodqa#16811, `harness/hooks/shell_words.py`): one shared shell-word scanner for the merge gate's review stamp and the copy_hygiene disk floor. It splits a line into commands, words and redirects only when bash and zsh read it the same way: unquoted text, single and double quotes, `$NAME`/`${NAME}`, the operators `;` `&&` `&` `||` `|&` `|` and newline, `(`/`)` subshells and plain redirects. For anything else it answers "cannot verify" and names why: a comment, a backslash, command or process substitution, arithmetic, ANSI-C or locale quoting, a heredoc, history expansion, a reserved word, a curly or other non-ASCII quote, space or format character, a control character, unbalanced quotes or more than 64 KiB. Both guards then fall back to their strict reading. A differential test runs every corpus line, including each reviewer example and the real refused shapes, through real bash and zsh with builtins and PATH disabled, and compares the commands they would run with the scanner's list. It compares against whichever of bash 4+ and zsh is installed, and is skipped only when neither is. Tests: `python3 -m unittest tests.test_shell_words_differential`.
- merge gate review stamp (goodqa#16811): a plain `peer_review.py pr` from main whose `--repeat-reason` holds `;`, `&`, `|`, `<` or `>` inside single or double quotes now mints the review-auth stamp. The line is read through shell_words, and only a POSIX shell tool (Bash, shell, local_shell, exec_command, unified_exec) mints. PowerShell reads curly quotes as quotes, so a PowerShell or write_stdin call mints nothing and says why. Single quotes are opaque. Inside double quotes any `$` or backtick is refused. These still mint nothing: a newline or other control character, a curly quote, `$'...'`, an unquoted backslash, `$`, `#`, operator or redirect, and unbalanced quotes. The binding comes from the same argv that was validated, and a repeated `--github-repo` or `--pr`, or a quoted word that only looks like one, cannot rebind it. Several forms that used to mint (`$'...'`, `$VAR`, `${...}`, a CR, tab or `#` comment, a repeated `--pr`) no longer do. For subagents a bound review is refused when any one command on the line names peer_review and then `--github-repo` or `--pr`, quoted text included, and when a line shell_words cannot verify names them anywhere. That covers interpreter options (`python3 -X utf8`, `-W`, `-O`), wrappers (`env`, `sudo`, `timeout`), `python3 -c` code and the scripts of `sh|bash|zsh -c`. A line that is not fully literal (an expansion, glob or brace, or a line shell_words cannot verify) is also refused for a subagent when its text names `peer` and a binding flag anywhere, in any order (`P=peer_review.py; ... $P`, `G=--github-repo; ... $G`, `peer_r*.py`). A launch built wholly at run time (`$(cat f)`, a wrapper script) cannot be seen in the text; the stamp is the authority control for those. peer_review.py takes main's stamp right after parsing its arguments, and burns it when argparse refuses the run (an unknown option, a bad value, `--help`), so a run that exits early (a usage error, a HEAD mismatch) leaves nothing behind for another process. A stamp is honoured only within 120 s of the launch that minted it, instead of 600 s. The stamp is now bound to main's one call (its `tool_use_id`, main's transcript and the transcript size), and peer_review.py takes it only while that call is still running, at both take points: a call that another hook denied, that the user rejected at the permission prompt or that failed to launch leaves nothing another process can take, and a payload without a `tool_use_id` or a readable `transcript_path` mints nothing and says why. A review started with `run_in_background` gets its "started in the background" result at once, so its stamp is marked `background` and accepts exactly one record of exactly that shape; a hook denial, a rejected permission, a launch error, any `is_error` result, an empty or non-string `backgroundTaskId`, a second record naming the call or a line naming it that does not parse ends it, PostToolUse keeps it, and PostToolUseFailure and PermissionDenied still delete it. It still dies at 120 s or at the first take. For both kinds of stamp, Claude Code's own copy records (`api-request-blob`, `data-flow-records`) no longer end a call: a replay over 40 real main transcripts found a `data-flow-records` line naming a call before its own result in 3 of 5255 foreground calls, which would have ended a stamp for those calls early; with the new rule every one of the 5255 foreground calls stays running until its own result and ends there, and 329 of 334 background starts are accepted (the 5 others were `is_error` results). Not controlled, and stated as limits: another process that runs the same bound review while main's call is live, or while it waits at a permission prompt, is taken for main; a background stamp stays takable until it is taken or 120 s pass, even when main's own process died before taking it; and a Codex Desktop root's rollout never names a `tool_use_id`, so for that root only the 120 s window and single use bound the stamp. When main's review mints no stamp, the hook says why as non-blocking context, and peer_review's own note names the cause and the single-quote rerun. Tests: `python3 -m unittest tests.test_merge_gate_quoted_review_stamp tests.test_review_stamp_lifetime tests.test_caller_identity`.
- copy_hygiene disk floor (goodqa#16811): a clone or `cp -a` inside the quoted remote command of a plain ssh is no longer charged to this machine's disk floor. Only the copy check changed (`copy_commands`); the delete and `/dev/shm` checks still read the payload.
  - **What is dropped.** Every command keeps the base reading, which splits on every separator even inside quotes. Exactly one shape is dropped: a plain remote ssh. It must sit on a line that shell_words verifies, with nothing on the line that may change what `ssh` runs: `alias`, `eval`, `source`, `.`, `hash`, `export` and similar builtins, a `PATH`-like assignment, `env -S`, or a program word built at run time.
  - **What counts as plain.** The program word is `ssh` or the system ssh by an absolute path. Wrappers such as `sudo`, `timeout` or `nice` are allowed, but no assignment. There is no `ProxyCommand`, `LocalCommand`, `KnownHostsCommand`, `Include` or `Match` option, and no `-F` or `-I`. Every option, option value and the host are spelled out, with no expansion, glob, brace or tilde. OpenSSH also parses options after the host, up to the first word that is not one, so that first word must start with literal text other than `-`. Run-time words after it are the far host's text.
  - **What is still charged here.** A command after the ssh. Every line shell_words cannot verify (a comment, ANSI-C quoting, a backslash, a local `$(...)` or backtick, an ssh heredoc, an unbalanced quote). `./ssh` or any other path to a program called ssh. Any ssh whose option words are built at run time (`ssh -o"$X" host`, `ssh "-$X" host`, `ssh host "-$X" ...`, `ssh ''"$X" host`, `ssh -i ~/k host`). Quoted text that a command other than ssh may run (`watch '...'`, `su -c '...'`), as the base read it. The code carried by `eval`, `alias`, zsh `aliases[x]=`/`functions[x]=`, `trap` and `env -S`/`--split-string` is read as a command line too, so `env -S 'cp -a r c #' ssh h x` and `alias ssh='cp -a r c'` (then `ssh h x`) are refused below the floor.
  - **Remote as well.** The clone inside `bash -c 'ssh h "cd x && git clone a b"'` runs on the far host and is not charged, but only when the script word holds no expansion. Wrapper options (`timeout 120`, `timeout -s KILL 5m`, `nice -n 5`, `sudo -u U`, `sh -c`) no longer hide a copy.
  - **Known gaps (true before this change as well).** A command hidden in a variable's value or in a file is not read: `C='git clone u d'; $C`, a sourced file, or `X='-oProxyCommand=git clone ...'; ssh "$X" h true`. That ssh gets the base reading, which cannot see inside `$X`. `ssh localhost`, or an alias of this machine, is treated as remote. A redirect of the remote output onto this disk, `ssh devbox 'tar c dir' > local.tar`, writes remote data here and is not counted (PR 334 review, F3). A double-quoted `-o` keyword (`-o '"PKCS11Provider" ./x.so'`, which OpenSSH accepts) is now refused below the floor: the keyword lookup drops double quotes, and PKCS11Provider and SecurityKeyProvider are matched in every word (F1). The real-ssh oracle test fails instead of skipping when the `CI` environment variable is set and ssh or both shells are missing (F2).
  - **Over-strict on purpose.** An ssh with `-i ~/key`, `--` or an option letter outside OpenSSH 9.x and 10.x gets the base reading.
  - **Tests.** A generated table of run-time option-word shapes (before the host, as an `-o` value, after the host, in the command). A guard test that only listed remote shapes escape the base reading. An oracle that runs each line under bash and zsh with `ssh -F /dev/null -G` and an injected `-oProxyCommand`. Run them with `python3 -m unittest tests.test_copy_hygiene_ssh tests.test_copy_hygiene tests.test_shell_words_differential`.

Only TEST words are exempt. Any other word, option, wrapper, runner or subcommand anywhere in the command keeps the full scan, so `-- env -C /srv tools/kill-all.py`, `-- npx tsx --tsconfig tsconfig.json tools/kill-all.ts` and `npx vitest run tools/kill-all.ts` block. Two forms are scanned in full again: generic script operands (`python3 tools/lint.py src/kill-switch.go`), and wrappers inside the pgpool line (`-- env CI=1 npx vitest run ...`). There is no per-repo or per-file allowlist. Tests: `python3 -m unittest tests.test_kill_guard_path_operands`.
- gq_browser `keys --orphans` (goodqa#16051, found by a click-tester): a deleted key is no longer listed. The server's DELETE revokes a key and its list keeps the revoked row, so a re-delete answered 404. Rows with `revokedAt` are skipped. Tests: `python3 -I tests/test_gq_browser.py -k deleted_key`.
- kill_guard false positive (goodqa#15365): a path glob in argument position of an ssh remote command (`ssh host 'ls tools/x/*'`) is no longer read as the command name `*` and refused as `[broad-kill]`. A glob in command position, and every real kill through ssh, still block. Tests: `python3 -m unittest tests.test_kill_guard_ssh_glob`.
- merge gate false positives (goodqa#15122): `git push gh <sha>:refs/heads/<feature>` (a remote named gh) is no longer read as a gh call; read-only gh calls whose words come from a literal variable in the same command pass; the subagent exception-record block allows only known free-text forms (notes through the harness helpers, commit messages, ticket bodies, print and search commands) and keeps the old text rule for every other program; any builtin that can assign (`printf -v`, `declare -n`, `trap`, `read`) makes literal variables unknown; pushes to `heads/main`, through `xargs`, or with alias or push config on the command line block. New: a `git push` to main or master, `--all`, `--mirror` or a destination built at run time blocks.
- command_guard false positive (goodqa#15122): removing or overwriting a command's own `mktemp` file, also with TMPDIR relocated under the harness and from a script file, is no longer refused as a protected harness directory; WAL and transcript deletes through a variable, a reassigned temp variable, a symlink or a TMPDIR pointing at protected logs stay blocked.
- log-backup bulk lane yields to tier 1 (goodqa#15147): the lane no longer splits the write budget. While a tier-1 run holds the run lock it makes no copy requests; a copy in flight stops within one poll plus the stop grace and its 300-file chunk is sent again whole, the cursor unchanged. Tier 1 always copies at the full rate. The plist ships the lane off until three tier-1 runs in a row finish inside the budget.
- log-backup bulk lane: on the Mac the bulk tier now runs as its own detached run beside tier 1, on a split of the
  same 2/s write budget, instead of in the few minutes tier 1 left (about 400 files an hour). Bulk chunks are 1000
  files. A pass is listed again when the exclude lists change, and five verified `.lanes` copies (about 230k files)
  are excluded with a pinned tag and a backed-up manifest (goodqa#15062).
- log-backup bulk lane review (PR #124): runs that share their 13 minutes keep 100-file chunks and every chunk fits
  the time left; the rate is split whenever a lane is live; an unsplittable limit turns the lane off instead of
  stopping every backup; the lane starts only when due and is confirmed; SIGTERM stops a run's own copy; opting out
  stops the lane; status shows it; the lane has its own log; exclude edits stop a pass at the next chunk.
- log-backup bulk tier: a pass now resumes from a checkpoint instead of starting over every run. With the 620k-file
  work tree, each run re-checked the same first files and the pass never finished. Files verified by an earlier pass
  are not checked again, and only new or changed files are sent (goodqa#15062).

### Added
- ops_watch `remote_units`: a read-only ssh check of a timer job on another host (for example t2-blog-drip on
  t2-dev). It alerts when the last run failed, when there has been no success within `max_age_h` (26 h), or when
  the unit is missing or its timer is stopped (goodqa#15070).
- command_guard `approve-delete --archive/--archive-sha256/--archive-listing`: approve a delete from one verified remote tar
  archive (.tar, .tar.gz or .tar.zst) when a file-by-file mirror is too slow; the guard streams and checks the archive
  itself (goodqa#15068).
- Heavy work off the Mac (goodqa#14817, P12). `heavy_job_guard.py` has a `copy` rule: cp, rsync, tar, ditto,
  `git clone`, `gh repo clone` and `git worktree add` are sized (bounded walk, `ssh du`, GitHub repo size) and
  refused at 1 GiB (`HARNESS_COPY_GIB`), unknown size counting as heavy. `HARNESS_LOCAL_OK` is limited to one use
  per owner per hour (`HARNESS_HATCH_PER_HOUR`), audited to the WAL and the alert ring (source `heavy-guard`), and
  never applies to a large copy above 85% disk. `ops_watch.py` gives each `work/<session>/<sub>` owner a 5 GiB disk
  budget (kit `disk_budget_gib` up to 20), alerts `disk:owner:<agent>` by name and writes
  `state/disk-budget/<agent>.json`; an over-budget owner cannot start a heavy copy. Nothing is killed or deleted.
  `install_codex.py` installs the guard for Codex (trust it in Codex `/hooks`).
- Heavy families off the Mac (goodqa#14817). `heavy_job_guard.py` now denies package installs (pnpm/npm/yarn/bun),
  replay/synthetic/stress/soak scripts and `k6 run`, docker/podman run, pull and compose up (remote engines are
  allowed), and backgrounded or looped `claude -p` (unquoted `&` only; the cap plus `HARNESS_LOCAL_OK` is the
  escape). `xargs -P` and `parallel` fan-out is enforced too. Each denial prints a runnable route: copy the
  checkout, then `ssh HOST bash -lc '<whole command>'`. Default host `t2-dev` (`HARNESS_ROUTE_HOST`); headless
  claude goes to `dev2` (`HARNESS_CLAUDE_ROUTE_HOST`) because claude is not logged in on t2-dev. Not covered:
  pip/uv/bundle installs, `codex exec`, `claude -p` in nested shells. `exempt_hosts` in `heavy_job_guard.json`
  switches the guard off on a heavy-work host such as the Mac mini.
- Dropbox upload lane (goodqa#14817). `heavy_job_guard.py` rule `dropbox-lane` (enforce) refuses an agent
  `rclone copy|copyto|sync|move|moveto|bisync` to a Dropbox remote (type from `rclone listremotes --long`, never the
  config file) without `--tpslimit` of at most 4, with more than 4 `--transfers`, or while another agent upload to
  Dropbox runs. The launchd log backup is never the lane holder. Dry runs, downloads and listings are allowed;
  `HARNESS_LOCAL_OK` applies. Two parallel unthrottled uploads stalled the log backup for 6 h on 2026-11-07.
- `command_guard.py`: `rm` of a top-level git clone needs no Dropbox backup when git proves it clean, with nothing
  untracked, and every local commit reachable from a remote-tracking ref that matches the live remote
  (`reproducible_clone` policy). Any doubt keeps the existing approve-delete rule.
- `scripts/leak_scan.py`: scans tracked files (or history with `--history [--range]`) for
  tokens, private keys, real home-directory names, private and shared-address-space (RFC 6598) addresses,
  tailnet names and a local denylist. It never prints a matched value, and exits 2 if
  nothing was scanned. Fixture paths with deliberately fake tokens go in `.leakscan-allow`.
- `commit_policy.local.json` overlay: personal values (org, repos, key location) are
  read from an untracked file beside `commit_policy.json`; `.example` shipped.
- `CHANGELOG.md` and `docs/FINDINGS.md`.
