## Outcome

After the next release through the release runner, the self-host production host has a locally built image for each of the four dispatcher job kinds, pinned by content address. The dispatcher starts every job kind whose env is ready instead of answering 422.

- Users get repo scan results and playable recordings (MP4 and poster) again.
- Suggest Fix and frame extraction start running too, but complete only once their missing env keys are provisioned. Project Intelligence and recording transcription stay HELD (not launched): intelligence to keep its backlog re-queueable, transcription so that nothing launches toward a VERTEX_AI_* path (the no-Vertex rule; goodqa#16144 owns the replacement provider). That is a separate, linked P0 ticket, and this ticket reports those kinds as partial (Level 1 only) until then.
- A release whose compose names a release-managed image the host lacks is refused before the switch.
- A job image that later stops resolving (pruned, untagged) is visible in `state` and alerted on, never silent again.

No production database query was used for #16136 by any route. The WAL intent wa3241a24b1a planned "SELECT/logs only" before the programme rule was restated. No query ran: the lead refused both proposed routes, and the dating and impact come from the compose pin history, host logs, code and the product API.
