# Agent Harness for Claude Code and Codex

Agent Harness is an engineering workflow for people who let Claude Code or Codex change real repositories, with several agent sessions running at once on subscriptions. It does not replace the vendors' agent loop.

Since release 1001 it stops judging what agents type and sets real boundaries in a few places instead ([docs/direction.md](docs/direction.md)):

- **The operating system** limits where a session can write and which secrets it can read: per-role sandbox and permission settings for Claude Code and Codex, generated by `ah sandbox`, proven on each host by `ah doctor` ([docs/sandbox.md](docs/sandbox.md), [docs/doctor.md](docs/doctor.md)). The installer writes them but turns nothing on: that is the owner's shadow step.
- **GitHub** refuses a merge without a passing independent review: `ah repo protect` sets the ruleset, and `peer_review.py pr` posts the `harness/review` status ([docs/merge-rule.md](docs/merge-rule.md)).
- **Small tools** handle the actions that matter outside the machine by checking the real object and proving the result: `ah secret`, `ah log-push`, `ah kill`, `ah worktree-remove`, `ah reap`.
- **Each session works in its own folder**; what it leaves is saved at every turn end and removed later by the reaper ([docs/lifecycle.md](docs/lifecycle.md)).

Ten hooks remain, and none runs on a Bash call ([docs/harness-reference.md](docs/harness-reference.md#hooks-release-1001)). Everything else is advice given once, or was deleted. Architecture: [docs/architecture.md](docs/architecture.md).

## Quick start

```sh
git clone https://github.com/ericmacdougall/agent-harness.git
cd agent-harness
```

**Claude Code** requires version **2.1.332+**, Python **3.9+** for the hooks (3.10+ to run the installer), and Git on macOS or Linux. Preview, install, then start a new Claude Code session:

```sh
python3 install.py
python3 install.py --apply
```

**Codex** requires a current local Codex with hooks and permission profiles, and Python **3.11+** for the installer. Preview, install, then start a new Codex session and use `/hooks` to review and trust the installed hooks:

```sh
python3.11 install_codex.py
python3.11 install_codex.py --apply
python3.11 install_codex.py --apply --default-role worker     # optional: new sessions run in the ah-worker profile
```

The Codex installer writes the three sandbox profiles (`ah-worker`, `ah-reviewer`, `ah-supervisor`) into `config.toml` between its markers and selects none unless you pass `--default-role`. An earlier install's `default_permissions = "agent-harness"` line becomes `"ah-worker"`; a `":danger-full-access"` line from an earlier `--default-full-access` is kept as it is, with a note. [Codex setup and limits](docs/codex.md). Windows has not been tested.

Flags removed in release 1001 fail loudly and say why: `--services`, `--no-provenance-hooks`, `--no-command-guard`, `--floor-watch`, `--no-floor-watch` (install.py) and `--no-command-guard`, `--default-full-access` (install_codex.py).

## Claude Code install details

The installer copies the agents and helpers into `~/.claude`, places a marked block in `~/.claude/CLAUDE.md`, and **merges** its ten hooks and narrow helper permission rules into `settings.json`. An upgrade removes every handler and allow rule an earlier release registered for a deleted script and keeps your own. Existing model, theme, deny rules and unrelated hooks are preserved. It backs up files it replaces under `~/.claude/agent-harness-backups`, validates payloads before writing and attempts to restore replaced files if a write fails. It also:

- writes `~/.agent-harness/sandbox/{worker,reviewer,supervisor}.claude.json` (mode 0600). Nothing loads them unless a session is started with `claude --settings <file>`; no managed settings are written and no role is selected;
- writes the switch shim `~/.agent-harness/bin/harness` (a different program found there is renamed to `harness.retired-<stamp>`, never deleted);
- unsets the `hook.agent-harness-commit-policy` commit-msg backstop an earlier release added to `~/.gitconfig`;
- on the real home, stops and deletes an old release's floor watcher (it rewrote `settings.json`; nothing does now except an explicit `install.py --apply`);
- sets `CLAUDE_CODE_TMPDIR` to `~/.agent-harness/scratch` (mode 0700) when you have not set your own; `--no-durable-tmp` removes the harness value and is remembered.

With `--log-backup` it schedules the log backup; with the default it installs the pinned [netwatch](https://github.com/ericmacdougall/netwatch) monitor (`--no-netwatch` skips it); see [operations](docs/operations.md). Mission Control stays as an optional read-only dashboard ([docs/mission-control.md](docs/mission-control.md)).

Claude Code's `--safe-mode` disables `CLAUDE.md` and hooks. Use a normal session when relying on the harness.

### Turning the harness off

`~/.agent-harness/bin/harness off` (or `python3 ~/.claude/hooks/ah_switch.py off`) silences every harness hook at once, in running sessions too, moves the harness block out of `CLAUDE.md`, and stops the harness background jobs. `harness off --keep-services` leaves the jobs running. `harness on` puts everything back, and `harness status` says which state you are in. A release floor stops installers from old checkouts from putting older hooks back; `harness floor-check` reports one that did. See [docs/off-switch.md](docs/off-switch.md).

To uninstall:

1. `harness off`, then remove the marked block from `CLAUDE.md` if it is still there.
2. Remove the hook entries in `settings.json` that run `~/.claude/hooks/ah_hook.py`, and the harness permission rules.
3. If installed, run `~/.agent-harness/bin/netwatch uninstall`, delete the binary, and pass `--no-netwatch` to any later install.
4. Remove the copied agents and helper scripts. Restore a backup if you want the exact earlier state.

## Operating model

1. The main agent scopes the request and assigns one owner to each nonoverlapping task. Each session works in `$AH_WORK`; `ah co <repo>` makes a checkout there.
2. The owner writes short notes (`wal_note.py --event intent|decision|ask|handoff`), implements in recoverable increments with failing-first tests, and runs focused checks.
3. Independent review comes before merge: `peer_review.py pr` reviews the exact head with a reviewer one rung above the author and posts `harness/review`. A fix after review is a new head and is reviewed again.
4. `deliver.py` publishes the feature branch and a draft PR, and after the merge fast-forwards the original checkout ([operations](docs/operations.md#delivery-workflow)).

Background jobs: `bg_job.py launch|wait|status` reports STARTED only on proof and returns a job's real exit status. `usage_guard.py` keeps finite command receipts. When `peer_review.py` cannot produce a result it prints a stable reason code and the exact next step ([review helper reliability](docs/operations.md#review-helper-reliability)).

The helpers are not a sandbox for repository code, tests, hooks or merge drivers; the per-role sandbox is ([docs/sandbox.md](docs/sandbox.md)). The main agent must invoke the tools and inspect the evidence.

## Evidence and limits

[Validation notes](docs/validation.md) distinguish automated helper tests from untested scenarios. A hook cannot prove that a test was meaningful, that a review was independent, or that a UI was clicked. The threat model and what each boundary does not cover are in [docs/direction.md](docs/direction.md) ("The never list").

This repository contains no account credentials, session logs, app fixtures, or machine-specific settings. The MIT license covers this harness; model and CLI products retain their own terms.

## Local gates

Run before pushing, from a clean tree: `python3 scripts/leak_gate.py --range origin/main..HEAD`.
It runs `scripts/leak_scan.py` on the tree and the pushed commits, and gitleaks
if installed and pinned by SHA-256 (`--gitleaks-sha256`). It needs your personal denylist
(`~/.agent-harness/leak-denylist.txt`, one regex per line, mode 0600, never committed) and
refuses to pass without one unless you pass `--no-denylist`. Matched values are
never printed.
