# Codex-native Agent Harness

This edition uses Codex's [global `AGENTS.md`](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [skills](https://learn.chatgpt.com/docs/build-skills), [custom subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), and [lifecycle hooks](https://learn.chatgpt.com/docs/hooks). It is a user-wide working agreement plus small local helpers, not a scheduler or proof that every model will follow every step.

## Install

Requirements: current local Codex with custom agents and hooks, Git, Python 3.11+, and macOS or Linux. The installer parses the existing and generated TOML before any write. On Python 3.10 and older, the Codex installer refuses to run; the unrelated Claude installer still supports Python 3.10. From a clone of this repo:

```sh
python3.11 install_codex.py                  # preview managed paths
python3.11 install_codex.py --apply          # merge and install
python3.11 -m unittest tests.test_install_codex -v
```

The installer puts a marked block in `~/.codex/AGENTS.md`, the skill in `~/.codex/skills/agent-harness`, role profiles in `~/.codex/agents`, the WAL writer in `~/.codex/agent-harness/wal.py`, and four managed entries in `~/.codex/hooks.json`. It also creates a private `~/.agent-harness/codex-wals` directory and defines a custom `agent-harness` permission profile in `~/.codex/config.toml`. A standard fresh install selects that profile; an existing user-owned default is preserved. The profile extends Codex's workspace policy and adds write access only for the private WAL path and workspace `.git` metadata, so agents can make recoverable local commits. It leaves unrelated model, plugin, and hook settings intact. If a legacy sandbox configuration is already set, the installer stops before writing; merge the policy manually. The profile does not grant network access for pushing.

If you explicitly want **built-in Full Access as the default for new sessions**, preview and apply with `python3.11 install_codex.py --default-full-access` and `python3.11 install_codex.py --apply --default-full-access`. This opt-in selects `default_permissions = ":danger-full-access"` and `approval_policy = "never"`: local commands have unrestricted filesystem and network access and do not pause for approval. The harness's instructions, hooks, and optional `agent-harness` profile remain installed. A later install without the flag preserves this choice. The flag refuses conflicting user-owned permission or approval settings rather than overwriting them. It also refuses legacy `sandbox_mode` or `sandbox_workspace_write` settings, which take precedence over permission profiles; inspect and back up those settings before manually removing them. The standard install remains the narrower default.

### Permission troubleshooting

The standard installed profile is the **default for new sessions**, not a restriction on an explicitly selected Full Access session. Check the effective local command policy with `codex doctor --summary` or the session's `/permissions` control. In a live Codex CLI 0.164.0-alpha.11.1 probe, the standard profile reported restricted filesystem and network access with approvals on request; explicitly selecting `default_permissions = ":danger-full-access"` and `approval_policy = "never"` reported unrestricted filesystem and enabled network access with no approval prompts. The latter permitted private WAL and workspace `.git` writes. Removing the installed default without selecting another suitable profile leaves ordinary `:workspace` sessions unable to make local Git commits or direct semantic WAL writes, although trusted lifecycle hooks still created metadata WALs in a live session. See the official [permissions](https://learn.chatgpt.com/docs/permissions) and [sandboxing](https://learn.chatgpt.com/docs/sandboxing) documentation.

The desktop app's built-in Browser has **separate website permissions**; changing Codex's local command profile does not allow a Browser origin. For a denied site, inspect the app's Browser site-permission settings and any site-specific allow or block entry; setting names can vary by app version. If the Browser tool reports a saved permission or managed-policy denial, record the exact origin and error, then stop retrying until the permission or session state changes. Continue other work; do not use a different browser or command surface to bypass the denial. A fresh chat may help if an older chat retains a stale permission state, but the user chooses whether to start one. See the official [Browser documentation](https://learn.chatgpt.com/docs/browser).

Originals are saved in a mode `0700` timestamped directory under `~/.codex/agent-harness/backups`, with a manifest. A caught write failure attempts rollback; crashes and concurrent edits may require restoring the private backup manually. Reinstalling updates the marked blocks and managed hook entries without duplicating them. The permission profile applies to new sessions; a session-level override can select a different policy and may block WAL notes or Git commits. Avoid `codex exec --ephemeral` for a task that needs subagents: in the live trial it could not create the owner's thread record.

If Codex appends unrelated TOML sections between the generated permission profile and its end marker, reinstallation moves those sections outside the managed block while preserving their bytes and parsed settings. The original file remains in the private backup. The installer refuses an edited managed profile, bare settings that could attach to it, managed permission descendants, or any move that changes TOML meaning. Reformatting the generated profile itself, including changing its line endings, requires a manual merge. A valid but unusual TOML `nan` value may also be refused by the conservative parsed-value comparison.

**Start a new Codex session and use `/hooks` to review and trust the installed user hook definition.** Codex skips untrusted non-managed hooks, including these, until their current hash is trusted. The installer does not bypass that safety check. If a hook changes in an update, review and trust it again. The global instructions and skill can still guide work when hooks are skipped, but automatic WAL entries are then absent. Existing Codex sessions may retain earlier instructions; restart them to load this setup.

## Operating model

Small localized reversible fixes stay in the main checkout with one focused check and a brief WAL. Substantive changes get a scope brief, one owner for each related area, recoverable feature commits, independent plan and exact-head review, proportionate red-team and live UI/API checks, and main-agent integration. The main agent keeps the user informed. A remote outage blocks publication, not local testing and delivery. The [skill](../codex/skills/agent-harness/SKILL.md) holds the workflow and loads [owner](../codex/skills/agent-harness/references/owner-workflow.md), [testing](../codex/skills/agent-harness/references/testing-and-evals.md), or [delivery](../codex/skills/agent-harness/references/delivery.md) detail as needed. Codex's native agent tools perform delegation; the role TOMLs select reviewer and rescue models where available.

The hook records session starts, prompt length, local tool name and input length, and subagent starts. It does not store prompt text or tool arguments. The model must add semantic notes for scope, decisions, checks, and handoff. The session or subagent start hook supplies the private WAL path; use:

```sh
python3 ~/.codex/agent-harness/wal.py note --wal ~/.agent-harness/codex-wals/SESSION_ID/main.jsonl --event intent --note 'Scoped intent without private values'
```

If the hook is unavailable, `python3 ~/.codex/agent-harness/wal.py start-manual` creates a private manual WAL. Keep WALs out of Git and review them before sharing. A hook can observe supported local tool paths but may not see hosted or specialized calls. Hook metadata proves a call was attempted; it does not establish test quality or model compliance. Custom agent instructions ask reviewers not to edit, but a role file does not give them a separate read-only sandbox; the parent session's permissions apply.

## Checks and recovery

The Codex-specific tests use disposable homes, failure injection at all 14 managed writes, symlink refusal, eight concurrent WAL writers, crash-tail recovery, metadata privacy, idempotent merge of foreign hooks and config, and preservation of user-owned permission settings. Run the full repo suite with `python3.11 -m unittest discover -s tests -v`. The installer uses the same pinned-directory, pinned-file, and rollback primitives as the Claude installer. Current validation results are in [validation.md](validation.md).

To undo the Full Access default while retaining the harness, select another permission mode for new chats, or remove the two harness-owned root lines (`default_permissions = ":danger-full-access"` and `approval_policy = "never"`) from `config.toml` and select your preferred default. Removing only the first line can leave approval prompts disabled in another mode. Start a new session and check `/permissions` or `codex doctor --summary`; an existing session may retain its earlier policy. To uninstall the harness, remove the marked block from `~/.codex/AGENTS.md`, the four entries invoking `~/.codex/agent-harness/wal.py hook` from `hooks.json`, and the copied role/skill files. Remove the managed `agent-harness` profile block and any harness-owned root permission/approval lines from `config.toml`. Preserve other hook groups and user-owned config. The private WALs and backups can be retained for recovery or removed after reviewing them; restore a private backup if you need the exact previous content.
