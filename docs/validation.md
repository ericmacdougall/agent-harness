# Validation record

This page separates observed behavior from intended workflow. Source fixtures and private Claude transcripts are not published.

## Automated checks in this repository

Run `python3 -m unittest discover -s tests -v` and `python3 -m compileall -q install.py harness tests`. The tests exercise guarded feature publication, rejected protected/stale pushes, a credential prompt under a real pseudo-terminal and a stalled local pre-push hook (both must return `BLOCKED_REMOTE` instead of hanging), merge conflict and failed-check rollback, dirty-checkout preservation, rejection of a subdirectory or unparseable check before any merge, installer preservation/idempotence/symlink refusal, tolerance of foreign hooks with empty `args`, private backup directories, and private WAL metadata including `.`/`..` session identifiers. The tests isolate Git from user and system configuration. CI is configured to run them on Ubuntu and macOS with Python 3.10 and the latest 3.x. Local remote fixtures use bare repositories and Git hooks, without network listeners. The terminal reader drains output even when it observes process exit before the output becomes readable. These are deterministic helper checks, not proof that an autonomous agent follows the whole workflow.

## Independent review and improvement, 2026-10-29

Fable reviewed PR #2 at Astra's head `2326f57` against `6d6e0ba` and reran the suite under Python 3.9.6 and 3.15.0 with Git 2.54.0 on macOS.

- **CI was failing on both latest-Python jobs** ([run 40993378972](https://github.com/ericmacdougall/agent-harness/actions/runs/40993378972): `ubuntu-latest, 3.x` and `macos-latest, 3.x` with Python 3.15.1 failed; both 3.10 jobs passed). Three integration regressions asserted hook-start markers or merge parents that never existed. Cause: since Python 3.12, `unittest` exits 5 when no test ran, and six fixtures contained only `import unittest`, so the check failed and the merge was aborted before the step under test. Reproduced locally: a directory with that module exits 0 on 3.9.6 and 5 on 3.15.0, and the same three tests failed on 3.15.0. Commit `01609be` gives the fixture one passing test; the three tests then pass on 3.15.0.
- **A stalled Git command stranded `index.lock`.** The runner sent SIGKILL to the process group, but Git removes its lock files only from its SIGTERM handler. A probe with a real `git merge --no-ff --no-commit` whose external merge driver stalled past `--timeout 1` returned `BLOCKED_LOCAL` with `merge_aborted: false` and left `.git/index.lock` plus three `.merge_file_*` files; a second attempt against the same checkout was blocked before any merge. Commit `51e90e2` sends SIGTERM first, waits up to two seconds, then SIGKILLs survivors. Against the previous runner the new real-Git regression failed with `Git could not remove its index lock` and the runner test failed with `child was killed without a chance to clean up`; after the change both pass, the lock is gone and the driver child does not survive. The `.merge_file_*` temporaries still remain because Git does not register them for signal cleanup; the operations doc states this. The pre-commit hook case was also probed: Git releases the index lock before running that hook, so Astra's conditional lock assertion there never triggered on either runner.
- **Not changed after review:** push destination resolution (`get-url --push --all`, single-destination rule, second-rewrite refusal via `ls-remote --get-url`) matches Git's documented `pushurl`/`pushInsteadOf`/`insteadOf` precedence and the split-remote regressions push to real bare repositories; a `remote.<name>.mirror` remote makes `git push` refuse an explicit refspec, so it cannot bypass the default-branch check. Installer preflight, payload reads, private backups, byte/mode restoration and incomplete-rollback reporting behave as the tests assert; FIFO and file-in-place-of-directory checks happen before any open or write.

Final local validation at `51e90e2`: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests` ran **54 tests**, OK, on both 3.9.6 and 3.15.0; `python3 -m compileall -q install.py harness tests` and `git diff --check` pass. Failure-path time now adds the termination grace: a command group that ignores SIGTERM costs up to two extra seconds before the kill.

Head `3a4c6e8` (these three commits plus this section) passed all eight jobs of the Ubuntu/macOS × Python 3.10/3.x matrix in both the [push run](https://github.com/ericmacdougall/agent-harness/actions/runs/40994833408) and the [PR run](https://github.com/ericmacdougall/agent-harness/actions/runs/40994839746); the latest-Python jobs used Python 3.15.1 and Git 2.56.0.
