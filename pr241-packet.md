## Outcome
`bg_job.py wait-remote --host H --file F --until-file-line TEXT --timeout S` waits for a line appended to a remote log, so the hand-written `until ...; done; cmd | tail` loop is no longer the easy path; an ssh reset (exit 255) is an infrastructure outcome (exit 5), not a task failure.

## Design (read bg_job.py cmd_wait_remote, _poll, _ssh_once, file_judged_by_guard)
- Fixed remote command: `/usr/bin/ssh` with fixed options and `--` before the host; the remote text is one template (exit 10 file absent, exit 11 not a readable regular file, then `wc -c`, then `tail -c +OFFSET+1 -- F | head -c 65536`) in which only the shell-quoted file and an integer offset vary. HOST is validated by a regex; FILE may not start with `~`, contain NUL or line breaks, or exceed 512 characters. The CLI has no way to change the binary or add ssh options. Remote needs a POSIX login shell.
- Matching: a fixed substring (not a pattern) in bytes APPENDED after the first successful look (default, so an earlier run's result in a reused log cannot end the wait); `--include-existing` for a run's own fresh log; `--from-offset N` for a log appended across runs (size taken before the launch). The offset advances by bytes received (never the reported size); the last len(TEXT)-1 bytes are carried between polls; a smaller size resets the offset and carry; a full 64 KiB read reads on at once but never past the deadline. The size line must match a bare integer, anything else (banner, empty, garbled) is UNPROVEN, never a reset. `--fail-line TEXT` ends the wait early with exit 1 and wins over the success text. Nothing from the remote file is printed.
- Exits: 0 LINE_FOUND; 1 FAIL_LINE_FOUND; 2 UNPROVEN (remote command failed, file unreadable, ssh refused: Permission denied, Host key verification failed or Could not resolve hostname, found by scanning up to 2000 bytes of stderr, no retry); 3 TIMEOUT (required --timeout, 1 to 86400 s, one high alert); 5 INFRA (a poll whose attempt and one retry both returned 255, or the 30 s per-call bound expired, `--max-infra-polls` times in a row, default 3, one high alert); 64 usage (bad arguments, or FILE refused by the guard).
- Guard parity (review F4): the found or timeout answer is a substring oracle over any remote file, so FILE (as written and as `~/FILE` for a relative path) is judged with command_guard `raw_credential` and a `decide("cat -- ...")` read check; an import failure refuses. `raw_credential` and not `raw_sensitive`, because run kits and logs live under ~/.agent-harness and ~/.claude (review H2). A path the guard does not know, a remote symlink, and a transcript the guard lets `cat` read are stated limits.
- `wait --ssh-job`: a job status of 255 prints `INFRA ... EXIT_STATUS=255` and exits 5; without the flag nothing changes. bg_lint's wait-loop-tail advice adds the wait-remote hint when the loop mentions ssh.
